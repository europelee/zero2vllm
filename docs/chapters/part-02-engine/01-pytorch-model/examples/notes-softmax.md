# 附注：softmax 为什么先减最大值

`attention_math.py` 里的分数都是个位数，减不减最大值看不出差别。这篇附注记录 `probs = masked_scores.softmax(dim=-1)` 这一行背后实际发生的事，以及它为什么不是“多算一遍”。配套示例见 [attention_math.py](attention_math.py)。

## 平移不变性提供的是许可，不是多余的操作

对任意常数 $c$：

$$
\operatorname{softmax}(z)_i=\frac{\exp(z_i-c)}{\sum_j\exp(z_j-c)}
$$

朴素写法 $\frac{\exp(z_i)}{\sum_j\exp(z_j)}$ 并没有“不做平移”，它只是隐式选了 $c=0$。所以问题不是要不要平移，而是选哪个 $c$：实数域里任取都行，浮点里 $c=0$ 恰好最危险，$c=\max_j z_j$ 最安全。平移不变性保证了更换 $c$ 不改变定义——没有这条性质，减最大值这个操作根本不成立。

“反正平移后结果一样”只在实数域严格成立，浮点里要看实现怎么选 $c$。朴素写法不减去任何量，$z$ 与 $z+1$ 的 `exp` 舍入不同，fp32 下两者结果并不逐位相等；而减最大值之后，$z$ 与 $z+1$ 被映射到同一组指数 $z-\max$ 上，结果反而逐位相同。也就是说，平移不变性在数值上是被减最大值“修好”的，而不是不必做它的理由。

脚本末尾的 `correct_probs` 是同一性质的应用：`torch.ones_like(scores)` 让可见位置全部 $+1$、屏蔽位置置 $-\infty$，结果仍与 `masked_fill` 逐位相同。

## 溢出与归零

`exp` 的输出被浮点范围截断，两头都有硬阈值。下表为二分实测：使 `exp(x)` 恰好上溢或舍入到 0 的 $x$。

| dtype | 上溢 | 归零 | 最小次正规数 |
| --- | --- | --- | --- |
| fp16 | $x>11.09$ | $x<-17.34$ | $5.96\times10^{-8}$ |
| bf16 | $x>88.72$ | $x<-92.75$ | $9.18\times10^{-41}$ |
| fp32 | $x>88.72$ | $x<-103.97$ | $1.40\times10^{-45}$ |
| fp64 | $x>709.78$ | $x<-745.13$ | $4.94\times10^{-324}$ |

不加平移时的坏结果与减最大值的对照（除标注外为 fp32）：

| 输入 | 朴素 `exp/sum` | 减最大值 | 机制 |
| --- | --- | --- | --- |
| `[1000,1001,1002]` | `nan` | `[0.0900,0.2447,0.6652]` | 分子分母同时上溢，`inf/inf` |
| `[-1000,-1001,-1002]` | `nan` | `[0.6652,0.2447,0.0900]` | 全部归零，`0/0` |
| `[88,88.5]` | `[0,0]` | `[0.3775,0.6225]` | 分母单独上溢，有限值除以 `inf` |
| `[12,13]`（fp16） | `nan` | 约 `[0.2690,0.7310]` | fp16 的上溢阈值只有 11.09 |

第三行最难发现：没有 `nan`、不报错，只是和不再等于 1。即使都在安全区间，精度也不同——`[1,0,2]` 的真值是 `0.2447284711`，朴素写法给出 `0.2447284609`（差 $1.0\times10^{-8}$），减最大值给出 `0.2447284758`（差 $4.7\times10^{-9}$）。

## 分母恒不小于 1

减最大值之后，最大那一项满足 $z_i-\max=0$，$\exp(0)=1$ 精确成立，因此

$$
\sum_j\exp(z_j-\max)\ \ge\ 1
$$

这是结构性保证，不依赖输入量级：分母不可能归零，除法不会出现 `0/0`；所有指数 $\le 0$，上溢也不可能发生。这两条才是减最大值真正堵死的失败。

## 局部归零依然存在

当某个分数比 $\max$ 小超过上表的归零阈值时，该项仍然归零，例如 fp32 的 `[0,-200]` 输出 `[1.0,0.0]`。区别在失败的范围：朴素写法让整行塌成 `nan`，减最大值只牺牲个别项。这些项本来就不影响结果，有两层理由：

- 能被归零的项必小于该 dtype 的最小次正规数。fp32 下是 $1.4\times10^{-45}$，相对分母（$\ge 1$）的贡献与 `eps` $=1.2\times10^{-7}$ 相差 38 个数量级。
- 更本质的是，它们即使不归零也进不了分母：浮点加法在 $x<\mathrm{eps}/2$ 时 $1+x=1$。fp32 的 `[0,-100]` 实测 `exp` 得到 `[1.0, 3.78e-44]`，第二项尚未归零，但分母仍是精确的 `1.0`。“项归零”与“项保留却被舍入掉”对结果没有区别。

因此准确的说法是：减最大值把下溢从“整行失效”降级为“牺牲低于精度下限的冗余信息”，它保证的是分母 $\ge 1$，而不是没有任何项归零。

## 两处真正会被下溢咬到的地方

1. **对数概率**。概率归零后 `log` 得到 $-\infty$。需要对数概率时（交叉熵、PPO 的 logprob）必须用 `log_softmax`：它计算 $(z_i-\max)-\log\sum_j\exp(z_j-\max)$，把结果留在对数域，`log_softmax([1000,1001,1002])` 返回 `[-2.4076,-1.4076,-0.4076]` 而不是 `nan`。
2. **fp16 阈值过低**。分数只差 $17.34$ 就会产生 0 概率，而真实模型的 attention 分数跨度常超过这个量级。这是 fp16 推理要求在 fp32 中累加 softmax、或改用 bf16（阈值与 fp32 同级）的原因。

## 减最大值也救不了的情况

- **整行全为 $-\infty$**：$\max=-\infty$，$-\infty-(-\infty)=\mathrm{nan}$。这是因果 mask 必须保留对角线的理由，也是 `attention_math.py` 写 `triu(1)` 而不是 `triu(0)` 的原因——每个位置至少看得见自己，行内必有一个有限值。
- **输入中出现 $+\infty$**：$\max=+\infty$，$\infty-\infty=\mathrm{nan}$。fp16 下单个乘积 $300\times300=90000>65504$ 就足以让 $QK^\mathsf{T}$ 溢出，这要靠 $1/\sqrt{D_h}$ 缩放和 fp32 累加解决，与 softmax 的稳定性无关。

## 代价与实现

减最大值不是“多算一遍”的浪费。逐元素 kernel 受内存带宽限制而非算力限制，$4096\times4096$ 的 fp32 行 softmax 实测：

| 实现 | 耗时 |
| --- | --- |
| `x.softmax(-1)`（融合 kernel，内部减最大值） | $5.52$ ms |
| 朴素 `exp` + 除法（2 个 kernel） | $9.35$ ms |
| 手写减最大值（5 个 kernel） | $15.55$ ms |

融合版的“多算”反而最快，因为多余的中间张量要反复读写内存。`torch.softmax([1000,1001,1002])` 返回正常值而不是 `nan`，说明库内部已经在做这件事。放到真实 Attention 里，这一项开销还要与 $QK^\mathsf{T}$、$AV$ 两个矩阵乘相比，占比更小。

FlashAttention 是同一个道理的流式版本：分块扫描时维护运行最大值，遇到更大的分数就用 $\exp(m_{\text{old}}-m_{\text{new}})$ 重缩放已累积的分母与输出，从而不必让整行分数同时驻留。
